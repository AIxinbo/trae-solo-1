# AI小说写作平台 - 产品需求文档 (PRD)

## 一、AI写小说的痛点与解决方案

### 痛点 1：上下文记忆断裂

**问题描述：**
大模型上下文窗口有限（200K token），长篇小说动辄几十万字，写后面的章节时模型已忘记前面章节的情节、伏笔、细节。

**解决方案：三重上下文注入架构**

```
┌────────────────────────────────────────────────────────────┐
│  第一层：近5章摘要压缩（100字/章）                            │
│  第二层：当前章节大纲节点（本章目标明确）                      │
│  第三层：角色设定卡片（仅注入当前出场角色）                    │
└────────────────────────────────────────────────────────────┘
```

- **短期记忆**：最近5章摘要 → 保持近期剧情连贯
- **中期记忆**：当前卷纲 → 保持主线方向
- **长期记忆**：角色设定卡 + 世界观文档 → 保持设定一致性
- **辅助手段**：章节写作时通过 RAG 检索历史相关事件

---

### 痛点 2：角色人设崩塌

**问题描述：**
AI 在长篇创作中经常让角色行为前后矛盾——温柔的角色突然暴躁，理智的角色突然冲动，角色忘记了之前知道的信息。

**解决方案：结构化角色卡片 + 自动注入**

```
角色卡片（结构化存储）：
  ├── 基本信息：姓名/年龄/性别/身份
  ├── 外貌描述：外观特征
  ├── 性格维度：外向度/理性度/情绪稳定性/道德倾向（离散值）
  ├── 背景故事：核心经历（200字内）
  ├── 核心动机：驱动角色的根本原因
  ├── 成长弧光：各阶段的性格/能力/目标变化
  ├── 关系网：与其他角色的关系类型和亲密度
  └── 知识清单：角色知道什么/不知道什么（防止知识溢出）
```

**写作时自动注入**：只注入当前章节出场角色的卡片，让 AI 知道"这个人此时此刻应该怎么表现"。

---

### 痛点 3：剧情逻辑漏洞

**问题描述：** 情节前后矛盾、时间线错乱、伏笔无人回收、力量体系崩溃。

**解决方案：多维度审查引擎**

| 审查维度 | 检查内容 | 技术手段 |
|---------|---------|---------|
| 时间一致性 | 角色年龄/事件顺序/季节变化是否矛盾 | 结构化时间线追踪 |
| 因果一致性 | 事件A→事件B的因果关系是否成立 | 事件链检测 |
| 能力一致性 | 角色战力/技能是否前后矛盾 | 能力状态追踪 |
| 伏笔回收 | 前面埋的伏笔是否按时回收 | 伏笔状态标记表 |
| 设定一致性 | 世界观规则是否被违反 | 设定规则校验 |

---

### 痛点 4：公式化/同质化

**问题描述：** AI 生成的内容千篇一律，套路化严重，缺乏新意和个性。

**解决方案：拆书学习 → 风格建模 → 个性化生成**

```
拆书分析 → 提取风格特征 → 建立风格向量 → 生成时注入风格
```

- **拆书分析**：分析爆款作品的叙事结构、节奏、用词习惯
- **风格模板**：将不同作品的风格特征结构化存储
- **风格注入**：生成时让 AI 参考特定风格或混合多种风格

---

### 痛点 5：爽点节奏失控

**问题描述：** AI 写的网文缺乏节奏感——要么平铺直叙，要么全程高能没有喘息。

**解决方案：爽点节奏模板 + 自动布局**

```
标准网文节奏模板（以10章为单位）：
  第1章：开篇悬念/冲突建立
  第2-3章：铺垫深化，制造期待
  第4章：小爽点（打脸/收获/突破）
  第5-6章：过渡+新线索
  第7-8章：矛盾升级
  第9-10章：大爽点（高潮/逆袭/反转）
```

- **爽点类型库**：打脸型、逆袭型、收获型、装逼型、情感型
- **密度控制**：每3-4章一个小爽点，每7-10章一个大爽点
- **情绪曲线**：自动生成章节基础情绪曲线，AI 按曲线写作

---

### 痛点 6：网文语感不对

**问题描述：** AI 生成的内容带有明显的"AI腔"——太书面、太正式、缺少网文特有的节奏感和口语化表达。

**解决方案：网文语料微调 + 即时润色**

- **Prompt 工程**：在 System Prompt 中注入网文写作规范
- **风格转化**：将 AI 的书面语转化为网文口语
- **AI 痕迹消除**：自动检测并改写"AI 腔"表述

---

### 痛点 7：缺乏结构化创作工具链

**问题描述：** 作者需要在大纲规划、角色设定、章节写作之间反复切换，现有 AI 工具没有提供完整的工作流支持。

**解决方案：全流程创作工具链**

```
拆书 → 提取大纲 → 设计大纲 → 审查大纲 → 创作角色 → 生成细纲 → 编写正文 → 审稿正文 → 修改章节
 ①       ②          ③           ④           ⑤         ⑥         ⑦         ⑧         ⑨
```

每个环节都有专用的 AI 辅助工具，数据在环节之间自动流转。

---

### 痛点 8：难以从爆款中系统学习

**问题描述：** 作者想学习成功作品，但靠人工阅读分析效率低，难以系统化提取可复用的写作方法论。

**解决方案：AI 拆书引擎**

```
拆书引擎输出：
  ├── 结构分析报告（起承转合/章节节奏）
  ├── 角色系统分析（主角配角关系网）
  ├── 爽点分布图谱（章节-爽点对应表）
  ├── 写作技巧提取（叙事手法/对话特点/描写风格）
  └── 可复用的创作模板（大纲模板/角色模板/节奏模板）
```

---

### 痛点 9：大纲与正文脱节

**问题描述：** 很多工具中，大纲是大纲、正文是正文，两者互不关联，写了正文后大纲就失去了意义。

**解决方案：大纲-正文双向联动**

```
修改大纲 → 自动更新章节目标 → AI 续写参考新大纲
修改正文 → 自动同步回大纲摘要
```

大纲节点和章节正文通过 ID 强关联，任何一方的修改都会影响另一方的生成。

---

### 痛点 10：批量创作效率低

**问题描述：** 写一章要来回调教 AI 多次，重复输入大量上下文，效率低下。

**解决方案：项目级上下文管理**

```
一次设置，永久有效：
  1. 创建项目时设定世界观/角色/风格 → 全局生效
  2. 生成任何章节自动注入相关上下文 → 无需重复输入
  3. 一键续写/扩写/改写 → 无需重复描述需求
  4. 批量生成功能 → 一次性生成多章，统一审查
```

## 四、产品愿景

**一句话定位**：让每个写作者都能从拆解爆款中学习，用结构化工具规划小说，用 AI 辅助高效创作。

**核心价值主张**：
- 不是"AI 替你写"，而是"AI 帮你写得更好"
- 从学习（拆书）到规划（大纲）到执行（写作）的全链路支持
- 结构化的创作流程保证长篇作品的连贯性和质量
