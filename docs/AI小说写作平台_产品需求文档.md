# AI小说写作平台 - 产品需求文档

## 一、AI写小说的痛点与解决方案

### 痛点 1：上下文记忆断裂

**问题描述：**
大模型上下文窗口有限（200K token），长篇小说动辄几十万字，写后面的章节时模型已忘记前面章节的情节、伏笔、细节。

**解决方案：三重上下文注入架构**

```
┌────────────────────────────────────────────────────────────┐
│  第一层：近5章摘要压缩（100字/章）                            │
│  第二层：当前章节大纲节点（本章目标明确）                      │
│  第三层：角色设定卡片（仅注入当前出场角色）                    │
└────────────────────────────────────────────────────────────┘
```

- **短期记忆**：最近5章摘要 → 保持近期剧情连贯
- **中期记忆**：当前卷纲 → 保持主线方向
- **长期记忆**：角色设定卡 + 世界观文档 → 保持设定一致性
- **辅助手段**：章节写作时通过 RAG 检索历史相关事件

---

### 痛点 2：角色人设崩塌

**问题描述：**
AI 在长篇创作中经常让角色行为前后矛盾——温柔的角色突然暴躁，理智的角色突然冲动，角色忘记了之前知道的信息。

**解决方案：结构化角色卡片 + 自动注入**

```
角色卡片（结构化存储）：
  ├── 基本信息：姓名/年龄/性别/身份
  ├── 外貌描述：外观特征
  ├── 性格维度：外向度/理性度/情绪稳定性/道德倾向（离散值）
  ├── 背景故事：核心经历（200字内）
  ├── 核心动机：驱动角色的根本原因
  ├── 成长弧光：各阶段的性格/能力/目标变化
  ├── 关系网：与其他角色的关系类型和亲密度
  └── 知识清单：角色知道什么/不知道什么（防止知识溢出）
```

**写作时自动注入**：只注入当前章节出场角色的卡片，让 AI 知道"这个人此时此刻应该怎么表现"。

---

### 痛点 3：剧情逻辑漏洞

**问题描述：** 情节前后矛盾、时间线错乱、伏笔无人回收、力量体系崩溃。

**解决方案：多维度审查引擎**

| 审查维度 | 检查内容 | 技术手段 |
|---------|---------|---------|
| 时间一致性 | 角色年龄/事件顺序/季节变化是否矛盾 | 结构化时间线追踪 |
| 因果一致性 | 事件A→事件B的因果关系是否成立 | 事件链检测 |
| 能力一致性 | 角色战力/技能是否前后矛盾 | 能力状态追踪 |
| 伏笔回收 | 前面埋的伏笔是否按时回收 | 伏笔状态标记表 |
| 设定一致性 | 世界观规则是否被违反 | 设定规则校验 |

---

### 痛点 4：公式化/同质化

**问题描述：** AI 生成的内容千篇一律，套路化严重，缺乏新意和个性。

**解决方案：拆书学习 → 风格建模 → 个性化生成**

```
拆书分析 → 提取风格特征 → 建立风格向量 → 生成时注入风格
```

- **拆书分析**：分析爆款作品的叙事结构、节奏、用词习惯
- **风格模板**：将不同作品的风格特征结构化存储
- **风格注入**：生成时让 AI 参考特定风格或混合多种风格

---

### 痛点 5：爽点节奏失控

**问题描述：** AI 写的网文缺乏节奏感——要么平铺直叙，要么全程高能没有喘息。

**解决方案：爽点节奏模板 + 自动布局**

```
标准网文节奏模板（以10章为单位）：
  第1章：开篇悬念/冲突建立
  第2-3章：铺垫深化，制造期待
  第4章：小爽点（打脸/收获/突破）
  第5-6章：过渡+新线索
  第7-8章：矛盾升级
  第9-10章：大爽点（高潮/逆袭/反转）
```

- **爽点类型库**：打脸型、逆袭型、收获型、装逼型、情感型
- **密度控制**：每3-4章一个小爽点，每7-10章一个大爽点
- **情绪曲线**：自动生成章节基础情绪曲线，AI 按曲线写作

### 痛点 6：网文语感不对 + 去AI味

**问题描述：**
AI 生成的内容带有明显的"AI腔"——过于书面化、句式工整、缺乏网文特有的节奏感。具体表现为：
- 过度使用转折词（然而、但是、不过、值得一提的是）
- 句子结构过于完整和平衡
- 缺乏口语化的随意感和"不完美感"
- 过度解释角色的情绪状态（"他感到非常愤怒"而非用动作表现）
- 形容词堆砌，缺乏网文的"爽利感"

**解决方案：六层去AI味机制**

#### 第一层：生成前 Prompt 约束

```markdown
在 System Prompt 中注入"反AI腔"指令：

写作禁忌（严禁使用）：
  ❌ 过度使用以下词汇：然而、但是、不过、值得一提的是、显而易见、
      毫无疑问、事实上、换句话说、简而言之
  ❌ 过度心理描写："他感到..."、"她意识到..."、"他心里想..."
  ❌ 工整的排比句
  ❌ 每段结尾的总结性句子

写作要求（必须遵守）：
  ✅ 用动作和对话表现情绪，而非直接描述
      ❌ "他感到非常愤怒"
      ✅ "他一拳砸在桌上，茶杯跳了起来"
  ✅ 句子长短结合，至少30%的短句（10字以内）
  ✅ 对话占比不低于40%（网文标准）
  ✅ 段落短小，每段不超过200字
  ✅ 适当使用口语化表达和语气词
```

#### 第二层：AI痕迹检测与消除

生成完成后，运行专门的"去AI味"检测Pass：

```json
{
  "ai_flavor_indicators": {
    "high_freq_words": [
      "然而", "但是", "不过", "值得一提的是",
      "显而易见", "毫无疑问", "事实上"
    ],
    "patterns": [
      "他感到", "她意识到", "他心里想",
      "在这一刻", "就在此时",
      "就这样", "如此一来"
    ],
    "sentence_patterns": [
      "过于工整的排比",
      "每段结尾总结句",
      "连续的形容词+名词结构"
    ]
  }
}
```

**检测规则**：
- 统计可疑高频词出现频率，每500字超过3次则标记
- 检测"他感到/她意识到"等心理描写标签，每章超过5次则标记
- 检测段落结尾是否有总结性句子
- 检测排比句使用频率

#### 第三层：参考范文注入

在 Prompt 中加入人类作者写的范文片段作为风格参考，让 AI 模仿其语感：

```
请参考以下范文的语感来写作：
[插入一段同类型网文的精彩片段]

特别注意范文的以下特点：
- 句子长短如何交替
- 对话如何推进情节
- 如何用动作代替心理描写
```

#### 第四层：多阶段生成策略

```
第一阶段：生成草稿（关注情节推进，不纠结措辞）
       ↓
第二阶段：改写去AI味（专门处理语感问题）
       ↓
第三阶段：精校（仅修正明显的语法错误）
```

每一阶段使用不同的 Prompt 和参数配置。第一阶段 temperature=0.8 鼓励创意，第二阶段 temperature=0.6 聚焦优化措辞。

#### 第五层：语感评分机制

生成后自动对文本进行"网文语感评分"：

| 评分维度 | 权重 | 评分标准 |
|---------|------|---------|
| AI词密度 | 25% | 每500字AI高频词≤2个得满分，每多1个扣10分 |
| 句子长度多样性 | 20% | 短句(≤10字)占比30-50%为佳 |
| 对话占比 | 20% | 对话占比40-60%为最佳区间 |
| "展示而非告知" | 20% | 用动作/对话表现情绪的比例 |
| 段落长度 | 15% | 平均段落≤150字为佳 |

**阈值**：语感评分 ≥ 75 分达标，否则自动触发第二轮改写。

#### 第六层：风格持续学习

记录用户对生成内容的修改（哪些句子被用户删了/改了），建立用户风格偏好档案：

```
用户风格档案：
  ├── 用户常删的词汇：[...]
  ├── 用户常改的表达：[...]
  ├── 用户偏好的句式：[...]
  └── 每次生成时自动参考该档案调整风格
```

### 痛点 7：正文章节字数不可控

**问题描述：**
AI 生成的章节字数不稳定——有时写2000字，有时写到6000字。用户希望字数精准可控（如每章3000±200字）。

**解决方案：三层字数控制体系**

#### 第一层：生成前的"字数预算"分配

将章节按"场景/事件"切分为多个段落，为每个段落分配字数预算：

```
章节目标：3000字
  ├── 场景1：冲突爆发（字数预算：800字）
  │   ├── 矛盾触发：200字
  │   ├── 双方对峙：350字
  │   └── 第一次冲突：250字
  ├── 场景2：势力介入（字数预算：700字）
  │   ├── 新角色登场：250字
  │   ├── 局势变化：250字
  │   └── 悬念设置：200字
  ├── 场景3：主角应对（字数预算：1000字）
  │   ├── 内心权衡：300字
  │   ├── 决策制定：300字
  │   └── 行动开始：400字
  └── 场景4：结尾悬念（字数预算：500字）
      ├── 意外出现：250字
      └── 章节尾声：250字
```

**实现方式**：在细纲生成阶段，就为每个场景标注目标字数。

#### 第二层：分段生成 + 字数自适应

```
生成流程：
  1. 从细纲中取第一个场景 + 字数预算
  2. 调用 AI 生成（Prompt 中明确要求：请用约800字写完这个场景）
  3. 检查生成字数：
     - 不足 → 触发扩写Pass（补充细节/对话/描写）
     - 超出 → 触发压缩Pass（精简描述/合并句子）
     - 达标 → 进入下一个场景
  4. 重复1-3直到所有场景生成完毕
  5. 汇总统计总字数

扩写Pass Prompt：
  "请将以下段落从500字扩展到700字。
  扩展方向：增加角色对话、补充环境细节、丰富动作描写。
  保持原有风格和节奏。"

压缩Pass Prompt：
  "请将以下段落从900字压缩到700字。
  压缩方向：精简修饰词、合并重复描述、保持核心情节完整。"
```

#### 第三层：逐句计数 + 实时反馈

在流式生成过程中，实时统计已生成字数：
- 已生成字数达到预算的90%时，在 Prompt 中注入收缩指令
- 已生成字数达到预算的110%时，自动截断并启动压缩Pass

```
字数控制器逻辑：

if (current_words < target_words * 0.8) {
    // 字数不足，保持正常生成
    continue;
} else if (current_words < target_words * 1.0) {
    // 接近目标，注入"准备结尾"指令
    inject("请开始收尾本章内容");
} else if (current_words > target_words * 1.1) {
    // 超出目标，截断并启动压缩
    truncate();
    run_compression_pass();
}
```

**总体误差控制**：±10%（如3000字目标，最终落在2700-3300字为合格）。

### 痛点 8：人物对话不够口语化

**问题描述：**
AI 生成的角色对话像"书面语朗读"——过于完整、过于礼貌、缺乏真实对话的随意感和个性差异。

**解决方案：四维对话优化体系**

#### 第一维：角色语音特征库

为每个角色定义独特的对话风格：

```json
{
  "character_id": "zhangsan",
  "speech_profile": {
    "style": "直爽型",
    "features": [
      "句子短，平均5-8字",
      "常用语气词：啊、嘛、呗",
      "喜欢反问句",
      "语速快，不爱停顿"
    ],
    "forbidden_words": [],       // 角色不会说的词
    "favorite_words": ["老子", "啥", "整"],  // 角色爱用的词
    "formality_level": 0.2,      // 0=极随意, 1=极正式
    "education_level": "low"      // 影响用词复杂度
  }
}
```

```json
{
  "character_id": "lisi",
  "speech_profile": {
    "style": "文雅型",
    "features": [
      "句子完整，平均12-15字",
      "很少用语气词",
      "使用成语和典故",
      "语速平稳"
    ],
    "forbidden_words": ["卧槽", "特么"],
    "favorite_words": ["确实", "不过", "依我之见"],
    "formality_level": 0.7,
    "education_level": "high"
  }
}
```

**系统预设角色类型模板**：

| 角色类型 | 对话特点 | 典型用词 |
|---------|---------|---------|
| 豪爽大侠 | 短句多，语气硬 | "兄弟、痛快、干" |
| 文雅书生 | 完整句子，用词讲究 | "确实、不过、如此" |
| 市井小民 | 俗语多，语气随意 | "得嘞、您嘞、整啥" |
| 冷面高手 | 字数极少，惜字如金 | "嗯、走吧、不必" |
| 活泼少女 | 语气词多，句式跳跃 | "哎呀、真的吗、好耶" |
| 阴险反派 | 话里有话，常用隐喻 | "呵呵、有意思、走着瞧" |

#### 第二维：对话场景规则

根据对话发生的社交场景调整语气：

```
场景类型 → 语气调整参数：
  ├── 私密对话（朋友/家人）：formality -0.3，语气词+1
  ├── 公开场合（宴会/会议）：formality +0.2，用词更谨慎
  ├── 冲突对抗（吵架/战斗）：句子更短，语气更强硬
  ├── 上下级对话（尊卑关系）：敬语+1，谦辞+1
  └── 亲密场景（情侣/家人）：语气词+1，省略号+1
```

#### 第三维：对话审查评分

生成后对对话部分进行专项评分：

| 评分维度 | 权重 | 检查内容 |
|---------|------|---------|
| 是否符合角色特征 | 30% | 用词/句式/语气是否匹配角色语音特征库 |
| 是否符合场景 | 20% | 正式度是否匹配当前社交场景 |
| 语法自然度 | 20% | 是否有"书面语对话"感 |
| 信息传递效率 | 15% | 对话是否在推进情节或塑造角色 |
| 差异性 | 15% | 不同角色的对话是否有明显区分度 |

**评分标准示例**：

```json
{
  "dimension": "是否符合角色特征",
  "checklist": [
    {"rule": "角色使用其标签词，每500字至少出现1次", "weight": 3},
    {"rule": "角色未使用其禁用词", "weight": 3},
    {"rule": "句子长度符合角色设定（±3字）", "weight": 2},
    {"rule": "语气强度（语气词数量）符合角色设定", "weight": 2}
  ],
  "scoring": "满分100，每违反一条扣除对应权重*10分"
}
```

**阈值**：对话评分 ≥ 70 分达标，否则触发改写。

#### 第四维：对话改写 Pass

```
对话改写Prompt：
"以下对话过于书面化，请改写成更自然的对话：

原文：
'这件事情确实非常棘手，我们需要认真考虑一下对策。'
'我完全同意你的看法，不如我们从长计议。'

改写要求：
1. 让两个角色说话方式有明显区别
2. 使用语气词使对话更自然
3. 句子不要太完整（真实对话常有省略和打断）
4. 考虑说话者的身份和关系

改写后：
'这事儿不好办啊。'
'那你说咋整？'
'我想想...'
```

### 痛点 9：章节审查与评分制

**问题描述：**
写完一章后缺乏客观的质量评估标准，用户不知道这章写得好不好、哪里需要改进。需要建立可量化的评分体系。

**解决方案：AI章节审查评分系统**

#### 审查维度与权重

| 维度 | 权重 | 满分 | 说明 |
|------|------|------|------|
| 剧情连贯性 | 25% | 100分 | 与前文逻辑衔接是否顺畅 |
| 人设一致性 | 20% | 100分 | 角色行为是否符合设定 |
| 爽点密度 | 15% | 100分 | 爽点数量与分布是否合理 |
| 节奏控制 | 15% | 100分 | 铺垫/冲突/高潮比例是否得当 |
| 对话质量 | 10% | 100分 | 对话是否自然且符合角色 |
| 去AI味语感 | 10% | 100分 | 是否有AI腔、语言是否自然 |
| 时间线一致性 | 5% | 100分 | 时间/年龄/事件顺序是否正确 |

**总分计算公式**：
```
总分 = 剧情连贯性×25% + 人设一致性×20% + 爽点密度×15% 
     + 节奏控制×15% + 对话质量×10% + 去AI味语感×10% 
     + 时间线一致性×5%
```

**判定标准**：
- 总分 ≥ 85：自动通过，标记为"已审"
- 总分 70-84：基本通过，附带改进建议
- 总分 60-69：不通过，标记问题，建议重写
- 总分 < 60：强制重写，提供详细的修改方向

---

#### 各维度详细评分标准

##### 1. 剧情连贯性（权重25%）

| 分数段 | 标准 | 检查项 |
|-------|------|--------|
| 90-100 | 与前文无缝衔接，伏笔自然 | 前文情节引用准确、因果逻辑自洽 |
| 70-89 | 基本连贯，1-2处小问题 | 存在微小逻辑跳跃但不影响理解 |
| 50-69 | 多处逻辑断裂 | 情节推进缺乏合理铺垫 |
| <50 | 与前文明显矛盾 | 事件与前面章节冲突 |

**AI审查Prompt思路**：
```
1. 读取前3章摘要 + 本章全文
2. 检查本章提到的事件/角色是否符合前文设定
3. 检查新的情节点是否有合理铺垫
4. 检查是否有"凭空出现"的信息或角色
```

##### 2. 人设一致性（权重20%）

| 分数段 | 标准 | 检查项 |
|-------|------|--------|
| 90-100 | 所有角色行为高度符合人设 | 对话、决策、反应都在角色性格范围内 |
| 70-89 | 主要角色一致，配角有小偏离 | 配角有1-2处不太符合但影响不大 |
| 50-69 | 多个角色出现人设偏离 | 角色做出了不符合性格的事却无合理解释 |
| <50 | 主角人设崩塌 | 角色行为与初始设定严重冲突 |

**AI审查Prompt思路**：
```
1. 提取本章所有出场角色的行为列表
2. 与角色的性格维度/动机/背景对比
3. 找出"这种行为是否合理"的证据
4. 特别注意：角色是否"知道"了本不该知道的信息
```

##### 3. 爽点密度（权重15%）

| 分数段 | 标准 | 检查项 |
|-------|------|--------|
| 90-100 | 爽点分布合理，节奏感强 | 每1500-2000字有一个爽点 |
| 70-89 | 有爽点但不够密集 | 每3000字左右有一个爽点 |
| 50-69 | 爽点太少或太密集 | 通篇平淡或全程高能 |
| <50 | 完全没有爽点 | 纯过渡或纯描写章节无冲突 |

**爽点识别规则**：

```python
pleasure_types = {
    "打脸型": "主角反击/碾压对手",
    "逆袭型": "主角从劣势翻盘",
    "收获型": "角色获得宝物/能力/信息",
    "装逼型": "主角展示实力让众人震惊",
    "情感型": "角色间情感升温/和解",
    "悬念型": "重大秘密曝光或新谜题出现",
    "战斗型": "精彩的动作/战斗场面"
}

def check_pleasure_density(chapter_text: str) -> dict:
    """检查爽点密度"""
    estimated_words = len(chapter_text)
    pleasure_count = count_pleasure_points(chapter_text)
    density = pleasure_count / (estimated_words / 1000)  # 每千字爽点数
    
    if density >= 0.5:  # 每千字0.5个以上
        return {"score": 90, "density": density}
    elif density >= 0.3:
        return {"score": 75, "density": density}
    elif density >= 0.1:
        return {"score": 60, "density": density}
    else:
        return {"score": 40, "density": density}
```

##### 4. 节奏控制（权重15%）

| 分数段 | 标准 | 检查项 |
|-------|------|--------|
| 90-100 | 张弛有度，段落长短交替 | 紧张场景与放松场景交替出现 |
| 70-89 | 节奏基本合理 | 偶有某段过长或过短但不影响整体 |
| 50-69 | 节奏失衡 | 通篇紧张导致疲劳，或通篇平淡 |
| <50 | 节奏完全失控 | 关键情节一笔带过，冗余描写过多 |

**节奏分析算法**：

```python
def analyze_rhythm(chapter_text: str) -> dict:
    """分析章节节奏"""
    paragraphs = split_paragraphs(chapter_text)
    rhythm_data = []
    
    for p in paragraphs:
        rhythm_data.append({
            "length": len(p),
            "has_dialogue": contains_dialogue(p),
            "emotion_intensity": estimate_emotion(p),  # 1-10
            "is_action": is_action_scene(p)
        })
    
    # 分析节奏合理性
    tension_peaks = [p for p in rhythm_data if p["emotion_intensity"] >= 7]
    rest_points = [p for p in rhythm_data if p["emotion_intensity"] <= 3]
    
    score = 100
    # 扣分项
    if len(tension_peaks) > len(rhythm_data) * 0.7:  # 全程高能
        score -= 20
    if len(rest_points) > len(rhythm_data) * 0.6:    # 全程平淡
        score -= 25
    if any(p["length"] > 300 for p in rhythm_data):   # 段落过长
        score -= 10
    
    return {"score": max(score, 0), "peaks": len(tension_peaks), "rests": len(rest_points)}
```

##### 5. 对话质量（权重10%）

| 分数段 | 标准 | 检查项 |
|-------|------|--------|
| 90-100 | 对话自然，角色区分度高 | 不看名字就知道谁在说话 |
| 70-89 | 对话基本自然 | 偶有书面语但不影响 |
| 50-69 | 对话生硬 | 像在"朗读台词"而非真实对话 |

##### 6. 去AI味语感（权重10%）

| 90-100 | 无AI痕迹，像人写的 | 句式多样，有"不完美"但自然的表达 |
| 70-89 | 轻微AI感 | 偶有工整句式但不明显 |
| 50-69 | 明显AI味 | 过度使用转折词，句式工整 |

### 痛点 10：人物和时间线前后不一致

**问题描述：**
长篇写作中，角色年龄、能力等级、事件先后顺序等容易出现矛盾——主角昨天还是筑基期今天就成了金丹期，某个事件在第3章发生在春天到第20章还是春天。

**解决方案：结构化时间线 + 角色状态追踪系统**

#### 全局时间线索引


```python
async def pre_generation_consistency_check(book_id: UUID, chapter_outline: str) -> List[Warning]:
    """新章节生成前的一致性检查"""
    warnings = []
    
    # 1. 时间连续性检查
    last_chapter_time = await get_last_chapter_time(book_id)
    new_chapter_time = extract_time_from_outline(chapter_outline)
    if new_chapter_time and last_chapter_time and new_chapter_time < last_chapter_time:
        warnings.append(Warning(
            severity="high",
            content=f"新章节时间({new_chapter_time})早于前一章时间({last_chapter_time})"
        ))
    
    # 2. 角色状态检查
    mentioned_characters = extract_character_names(chapter_outline)
    for char_name in mentioned_characters:
        char = await get_character(book_id, char_name)
        current_state = char.get_current_state()
        
        # 检查角色位置
        if "location" in chapter_outline and current_state["location"] not in chapter_outline:
            if not has_travel_narrative(chapter_outline, char_name):
                warnings.append(Warning(
                    severity="medium",
                    content=f"{char_name}上一章在{current_state['location']}，新章未交代移动"
                ))
    
    # 3. 知识一致性检查
    for char_name in mentioned_characters:
        char = await get_character(book_id, char_name)
        known_info = char.get_known_info()
        # 检查大纲中是否要求角色知道"不该知道"的信息
    
    return warnings
```

```python
async def post_chapter_consistency_check(chapter_id: UUID) -> ReviewResult:
    """章节生成后的一致性检测"""
    chapter = await get_chapter(chapter_id)
    previous_chapters = await get_previous_chapters(chapter.book_id, chapter.sort_order)

    # 4. 人物关系检测
    relation_issues = check_relation_consistency(chapter)
    issues.extend(relation_issues)
    
    # 5. 知识边界检测
    knowledge_issues = check_knowledge_boundary(chapter)
    issues.extend(knowledge_issues)
    
    return ReviewResult(
        passed=len([i for i in issues if i.severity == "high"]) == 0,
        issues=issues,
        score=calculate_consistency_score(issues)
    )
```

### 痛点 13：大纲与正文脱节

**问题描述：**
很多工具中，大纲是大纲、正文是正文，两者互不关联，写了正文后大纲就失去了意义。

**解决方案：大纲-正文双向联动**

```
修改大纲 → 自动更新章节目标 → AI 续写参考新大纲

```

大纲节点和章节正文通过 ID 强关联，任何一方的修改都会影响另一方的生成。

### 痛点 14：批量创作效率低

```
  3. 一键续写/扩写/改写 → 无需重复描述需求
  4. 批量生成功能 → 一次性生成多章，统一审查
```

## 四、产品愿景

**一句话定位**：让每个写作者都能从拆解爆款中学习，用结构化工具规划小说，用 AI 辅助高效创作。

**核心价值主张**：
- 不是"AI 替你写"，而是"AI 帮你写得更好"
- 从学习（拆书）到规划（大纲）到执行（写作）到审查（评分）的全链路支持
- 结构化的创作流程保证长篇作品的连贯性和质量
- 可量化的质量评分让作者明确知道改进方向
